# 작업 일지 (worklog)

Claude Code 가 이 저장소(배송·라이더 가상 현장)에서 한 작업의 "무엇을·왜·어떻게 검증했는지" 기록. 날짜별 1파일(`YYYY-MM-DD.md`), 항목은 시간순.
형식은 `../pmart-backend/docs/worklog/README.md`·`../pmart-mfc-simulation/docs/worklog/README.md` 를 따른다. **다른 PC 에서 이어 작업할 때 이 일지가 인수인계 문서다.**

## 규칙
1. **커밋 없이 일지만 쓰지 않고, 일지 없이 커밋하지 않는다.** 커밋할 때 같은 커밋에 일지 항목을 포함한다(커밋 SHA 는 다음 항목 또는 같은 항목에 추기).
2. **실행한 검증만 적는다.** 실행하지 않은 테스트·빌드는 "미실행"으로 미결에 둔다.
3. 구조에 영향을 주는 결정은 일지에 적은 뒤 `docs/design.md`(§10 결정 이력)·`CLAUDE.md` 로 옮긴다. 일지는 결정 문서를 대체하지 않는다.
4. 비밀정보·개인정보·토큰은 적지 않는다(고객 주소·전화번호 포함).
5. **백엔드 확인 기록**: `../pmart-backend` 를 읽어 확인한 사실은 근거(파일·커밋)와 함께 적는다. 백엔드는 읽기만 하며, 필요한 변경은 `docs/backend-requests.md` 에 적고 일지에는 "R-xx 추가/갱신"으로 남긴다.
6. 다른 PC 로 넘길 때는 마지막 항목의 "미결"에 **다음에 할 일**을 구체적으로 적는다.

## 항목 형식
```markdown
## HH:MM 제목
- 요청: 사용자의 말(요약 또는 인용)
- 한 일: 변경한 파일·범위
- 백엔드 확인: 읽은 파일·커밋과 확인한 사실 (없으면 생략)
- 결정: 선택과 근거 (대안이 있었으면 한 줄)
- 검증: 실행한 명령과 결과. 문서만 바꾼 경우 "문서만 — 시험 미실행"
- 미결: 남은 것, 가정, 확인 필요, 다음에 할 일
- 커밋: SHA
```
